# Credencial exclusiva del ejecutor de Supabase

Sites guarda `SUPABASE_RUNNER_SECRET` como secreto de runtime. Supabase Vault
guarda `fabrica_sites_runner_key` y `fabrica_sites_service_bearer`. Ningún valor
se incluye en el código, el navegador, esta documentación o los recibos.

La verificación de servicio usa POST al `/internal/runner` del Site original,
sin cuerpo, con `OAI-Sites-Authorization` y `x-supabase-runner-key`. No mezclar
esta cabecera con `x-agent-runner-key`, reservada al ejecutor existente de GitHub.
La credencial nueva no admite contexto GitHub ni declaraciones de programación.
Respeta la pausa global y utiliza la misma cola y el mismo bloqueo del trabajador.

El recibo se identifica como `supabase-service`, queda separado en
`supabase_service_receipt` y no reemplaza el recibo principal de GitHub. Una
comprobación manual de acceso no acredita un disparo automático ni una cadencia.

No se ha instalado ni activado un cron por configurar estas credenciales.
La integración del disparador automático requiere una fase independiente con
procedencia Supabase, recibos correlacionados y cambio explícito del principal.

La clave de GitHub y la del CRM se conservan. Si se revoca esta integración,
retirar únicamente `SUPABASE_RUNNER_SECRET` y los dos secretos de Vault de arriba;
no rotar credenciales compartidas como efecto secundario de una comprobación.
